# J-VOCA

일본어 교재 사진에서 단어를 추출하고, AI 예문과 FSRS 간격 반복으로 학습하는 모바일 우선 PWA 단어장.

## 사용법

1. [J-VOCA](https://ukiband.github.io/j-voca/)에 접속합니다. 기존 단어와 예문은 키 설정 없이 열람·복습할 수 있습니다.
2. 단어를 추가하려면 설정에서 Gemini API 키와 GitHub PAT를 입력합니다. 용도와 권한은 [키 설정](#키-설정)을 참고하세요.
3. 입력 탭에서 Step·레슨을 확인하고 교재를 촬영하거나 사진을 선택합니다. 추출 결과의 표기·읽기·뜻을 확인하고 수정한 뒤 저장합니다. 동사는 사전형 여부와 동사 분류도 확인합니다.
4. 단어 탭에서 Step·레슨과 검색어로 단어를 찾고, 듣기 모드에서 일본어/한국어, 반대 언어 정답 추가, 생각할 시간을 선택해 재생합니다. Step의 **전체**를 선택하면 모든 Step에서 검색하고, 단어마다 Step·레슨을 함께 표시합니다.
5. 복습 탭에서 전체 또는 레슨별 복습을 선택합니다. 일→한/한→일 방향과 랜덤/순차 순서를 선택하고, 카드를 탭해 정답과 예문을 확인한 뒤 모름/애매/앎으로 평가합니다. 평가하면 효과음과 함께 다음 카드로 넘어갑니다. 효과음은 iPhone 무음 스위치와 상관없이 음량 버튼으로 조절합니다.
6. 활용형을 외우려면 홈의 **동사 활용**을 선택합니다. て형·ない형·た형·가능형 중 원하는 형태를 체크하고, 사전형을 보고 변환한 뒤 정답과 규칙을 확인합니다. 정답 화면은 본문 아무 곳이나 탭하면 효과음과 함께 다음 문제로 넘어가며, 학습 기록에는 반영하지 않습니다.

iPhone의 Safari 또는 Android의 Chrome에서 **홈 화면에 추가**하면 앱처럼 사용할 수 있습니다.

## 주요 기능

- **사진에서 단어 추출**: 교재의 새 단어 정리 칸, 손글씨 단어·문장, 손글씨 뜻이 붙은 인쇄 표현을 추출합니다. 저장 전에 수정·제외할 수 있고, 같은 Step·레슨에 이미 있는 동일 표기의 단어는 건너뜁니다.
- **교재별 관리**: Step(교재 단계) > Lesson 구조로 분류합니다. 단어의 표기·읽기·뜻 수정, 개별 삭제, 레슨 전체 삭제를 지원합니다.
- **간격 반복 복습**: FSRS가 다음 복습 시점을 계산합니다. 일반 복습은 날짜 단위, 학습·재학습 단계의 재확인은 시각 단위로 대상을 고릅니다. 모름(Again)으로 평가한 단어는 같은 세션에서 다시 나옵니다.
- **복습 방향·순서 선택**: 일→한/한→일, 랜덤/등록 순서(ID 오름차순)를 지원합니다. 전체·레슨별로 복습하며, 태그가 있는 단어는 카테고리별 복습도 가능합니다.
- **날짜·시간 질문**: 홈에 들어오거나 홈을 띄운 채 앱으로 돌아오면 「今日は何月何日ですか」「今、何時何分ですか」 두 질문을 함께 팝업으로 묻습니다. 정답에는 한자와 숫자를 모두 히라가나로 읽은 줄을 함께 표시하며, 자정·정오는 午前12時·午後12時로 표기합니다. 속으로 답한 뒤 정답을 확인하고, 닫으면 1시간 동안 다시 묻지 않습니다. 설정에서 끌 수 있습니다.
- **동사 활용 연습**: 모든 Step에서 사전형으로 등록된 동사를 대상으로 て형·ない형·た형·가능형을 동적으로 계산합니다. 체크한 형태의 유효한 조합을 최근 Step·Lesson의 동사부터 출제하고 같은 Lesson 안에서는 섞어서 냅니다. 등록된 항목마다 출제하므로 같은 동사가 여러 Lesson에 있으면 Lesson마다 나오며, 예문·학습 기록·복습 일정과 별개로 연습합니다. 선택한 형태만 기억하고, 다시 들어오면 새 연습으로 시작합니다.
- **예문 학습**: 복습 카드의 뒷면에 일본어 예문, 읽기 문장, 한국어 번역을 표시합니다. 아래 읽기 문장은 한자를 히라가나로 풀고 가타카나와 조사 표기는 그대로 유지합니다. 예문과 읽기에서 학습 단어의 활용형을 강조합니다.
- **한자 학습**: 복습 정답의 단어·예문이나 듣기 화면에 표시된 일본어 단어에서 한 글자를 누르면 화면을 크게 채우는 팝업에 한국어 뜻·음독·훈독과 일본어 획순을 표시합니다. 획순은 한 번 재생하고 완성된 글자에서 멈춥니다. 상단 닫기 왼쪽의 **다시 보기**로 처음부터 재생합니다. 큰 한자 표시 영역은 빈 여백을 포함해 누르거나 손가락으로 따라 그려도 팝업이 닫히지 않습니다. 닫기 버튼이나 한자 표시·다시 보기 이외의 영역을 누르거나 Escape를 누르면 원래 화면으로 돌아갑니다. 듣기 모드에서는 한자를 여는 순간 연속 듣기를 멈춥니다. 6,417자 데이터를 묶음별로 불러오며, 처음 조회할 때는 연결이 필요하고 받은 묶음은 오프라인에서도 조회할 수 있습니다. [데이터 출처·갱신 방법](public/data/kanji/README.md).
- **한자 뜻 배경 그림(시험)**: 설정에서 켜면 한자 뒤에 뜻을 연상하는 단순한 선 그림을 옅게 표시합니다. 기본은 꺼짐이며 선택을 이 브라우저에 저장합니다. Step 2 · Lesson 2 단어의 56자만 제공하며, 예문에만 있는 다른 글자는 기존 화면을 유지합니다. 같은 글자는 다른 레슨에서도 그림을 볼 수 있습니다. AI 호출 없이 저장된 SVG를 불러옵니다. [시험 자료 설명](public/images/kanji/README.md).
- **듣기**: 검색·필터 결과를 섞어 일본어 또는 한국어로 연속 재생하고, 원하면 반대 언어 정답을 추가합니다. 생각할 시간은 0~15초(기본 5초)로 조절하며 발음이 끝난 뒤부터 셉니다. 정답을 추가하면 정답 전까지, 추가하지 않으면 다음 단어 전까지 기다립니다. 정답 뒤에는 2초 후 다음 단어로 이동합니다. 정답 텍스트도 정답 음성이 나올 때 표시합니다. 선택한 옵션은 저장하며, 옵션 변경은 재생을 멈추고 현재 단어부터 다시 시작할 준비를 합니다. 정지 후 재생하면 현재 단어부터 다시 읽고, 완료 후 다시 듣기는 처음부터 시작합니다. 지원 기기에서는 재생 중 화면 꺼짐을 방지합니다. 휴대폰 잠금·백그라운드 상태에서의 연속 재생은 보장하지 않으며 실제 기기에서 확인해야 합니다.
- **듣기 화면 잠금**: 재생 중 상단 자물쇠를 누르면 화면이 검게 바뀌고 설정·이동·닫기 조작이 차단됩니다. 듣기는 계속 진행합니다. 하단 버튼을 2초간 누른 뒤 손을 떼면 해제되며, 키보드 Enter 또는 Escape로도 해제할 수 있습니다. 짧게 누르거나 누르던 손을 버튼 밖으로 옮기면 해제되지 않습니다. 휴대폰 자체를 끄는 잠금이 아니라 앱 안의 터치 잠금입니다.
- **학습 현황**: 전체 단어 수, 현재 복습·재확인 대상 수, 세션 완료 시 평가별 횟수를 표시합니다.
- **백업·설정**: JSON으로 학습 기록을 내보내고 가져올 수 있습니다. 화면 테마(시스템·라이트·다크), 글자 크기 4단계, 날짜·시간 질문 팝업 켜기/끄기와 학습 기록 초기화를 지원합니다. 테마 기본값은 시스템이며, 선택은 해당 브라우저에 저장됩니다.
- **GitHub 동기화**: 단어 추가·수정·삭제를 저장소에 커밋하고, 앱 시작 시 최신 단어 데이터를 받습니다.
- **PWA·업데이트 알림**: 홈 화면 설치와 이미 받아 둔 데이터의 오프라인 학습을 지원합니다. 앱 시작·화면 복귀·홈 진입·네트워크 복구 시 새 배포를 확인하며, 주기적인 확인은 하지 않습니다. 현재 실행 중인 버전과 다르면 홈 화면에서 업데이트를 안내하며, 이미 최신 버전이면 버튼을 표시하지 않습니다.

## 예문 생성과 갱신

예문은 [GitHub Actions 워크플로](.github/workflows/generate-sentences.yml)가 Gemini로 생성·검사하고, 앱은 저장된 예문을 받아 표시합니다.

- **정기 생성**: 매일 한국 시간 오전 7시에 실행하도록 설정되어 있습니다. 등록일(`createdAt`)과 오늘의 날짜 차이가 0~7일인 단어가 대상입니다.
- **신규 등록**: 앱에서 새 단어를 저장하면 배치 실행을 요청합니다. PAT에 Actions 쓰기 권한이 없거나 요청에 실패하면 정기 실행에서 처리합니다.
- **교체 주기**: 단어당 예문은 1건을 유지하며, 대상 단어의 예문을 하루 한 번 새 문장으로 교체합니다. 현재 단어 내용과 일치하는 예문을 같은 날 이미 생성했다면 건너뛰고, 등록 후 7일이 지나면 마지막 예문을 유지합니다.
- **생성 한도**: 한 번 실행할 때 10단어씩 최대 5묶음(50단어)을 처리합니다. 한도를 넘긴 단어는 다음 실행으로 넘깁니다. 생성에 실패한 경우 단어 내용과 일치하는 기존 예문은 유지합니다.
- **읽기 검증**: 한자·숫자의 읽기와 띄어쓰기를 제외하면 원문의 가타카나·히라가나·문장부호·강조 위치가 유지되어야 저장합니다. 숫자와 조수사의 읽기(예: `300円 → さんびゃくえん`)는 허용합니다. 이 검사는 표기 대응만 확인하며, 한자의 실제 발음·문법·번역의 정확성은 이어지는 예문 검사에서 확인합니다.
- **예문 검사**: 같은 워크플로가 생성 결과를 먼저 커밋한 뒤 검사 배치를 실행하고, 검사 결과는 별도 커밋으로 반영합니다. 검사가 실패해도 그날 생성한 예문은 이미 반영되어 있습니다. 생성일(`date`)과 오늘의 날짜 차이가 0~7일이고 아직 검사하지 않은 예문과, 숨긴 날(`check.date`)과 오늘의 날짜 차이가 0~7일인 숨긴 예문이 대상입니다. 생성일과의 날짜 차이가 7일을 넘어 고정된 예문은 검사하지 않습니다.
- **검사 항목**: 문법과 자연스러움(조사·활용·いる/ある 등), 목표 단어의 쓰임(등록한 뜻·읽기, 강조 범위), 읽기 문장의 한자·숫자 읽기, 번역의 정확성(시제·긍정/부정·존댓말/반말 등), 원문의 공백·반각 문장부호를 확인합니다. 활용형 사용이나 등록 표기의 띄어쓰기를 붙여 쓴 것처럼 틀리지 않은 차이는 틀림으로 보지 않도록 프롬프트에 명시했습니다.
- **판정 기준**: 틀렸다는 판정은 어긴 검사 항목을 함께 받은 경우에만 반영합니다. 어긴 항목 없이 틀렸다고 한 판정은 1차 검사에서는 판정을 받지 못한 것으로 두고, 재검사에서는 수정안이 통과하지 못한 것으로 처리합니다. 잘못된 판정이 맞는 예문을 바꾸거나 숨기지 않도록, 검사는 생성보다 높은 사고 수준(3.5-flash-lite 의 `thinkingLevel: HIGH`)으로 요청합니다.
- **보정·재검사**: 틀렸다고 판정한 예문은 함께 받은 수정안이 저장 규칙(읽기 검증 포함)을 통과하면 한 번 더 검사하고, 재검사를 통과하면 수정안으로 교체합니다.
- **숨김과 재시도**: 검사 전 예문의 수정안이 저장 규칙이나 재검사를 통과하지 못하면(한도 등으로 재검사하지 못한 경우 포함) 원래 예문을 앱에서 숨깁니다. 숨긴 예문은 숨긴 날과 오늘의 날짜 차이가 0~7일인 동안 다시 검사하며, 재검사까지 통과한 수정안으로 교체될 때만 바뀝니다. 원문이 통과로 판정되거나 다시 틀렸다고 판정되어도 숨김과 기존 판정 기록을 그대로 유지하고, 날짜 차이가 7일을 넘도록 고치지 못하면 숨긴 채로 두고 더 검사하지 않습니다(그 건수는 배치 로그와 Actions 요약에 표시). 1차 검사에서 판정을 받지 못한 예문은 상태를 바꾸지 않고 다음 실행에서 다시 검사합니다. 숨긴 채로 남은 예문은 `sentences.json`에서 그 항목의 `sentence`·`reading`·`meaning`을 직접 고치고 `check`를 지우면 다시 표시됩니다(고친 문장이 저장 규칙에 맞는지는 `npm run test`로 확인). 이때 검사 전 상태가 되지만, 항목의 `date`와 오늘의 날짜 차이가 7일을 넘으면 검사 대상이 아니어서 다시 검사하지 않습니다.
- **검사 한도**: 10건씩 묶어 요청하며, 한 번 실행할 때 1차 검사는 최대 6회, 재검사는 최대 2회 요청합니다. 재검사 몫을 따로 두어, 숨긴 예문을 다시 검사하느라 1차 검사가 한도에 닿아도 새 예문의 수정안을 재검사할 수 있습니다. 1차 검사 한도를 넘긴 예문은 다음 실행으로 넘기고, 재검사 한도를 넘긴 수정안은 재검사를 통과하지 못한 것으로 처리합니다.
- **로컬 실행**: `GEMINI_API_KEY=... node scripts/check-sentences.mjs`로 검사 배치를 실행합니다. `--dry-run`을 붙이면 판정과 처리 결과만 출력하고 `sentences.json`은 바꾸지 않습니다.
- **앱 반영**: 앱 시작, 화면 복귀, 복습 진입 시 예문을 다시 받습니다. 시작 시 강제 갱신을 제외하면 마지막 성공 이후 최소 10분 간격을 둡니다. 진행 중인 복습 세션은 처음 읽은 예문을 유지하며, 새로 받은 예문은 다음 복습부터 표시합니다.

### 단어를 수정했을 때

`sentences.json`의 `source`는 **예문 생성 당시 단어의 표기·읽기·뜻**을 보관합니다. 현재 단어와 하나라도 다르면 기존 예문을 화면에서 숨깁니다. `source`만 최신 값으로 덮어쓰면 옛 내용으로 만든 예문이 유효한 것으로 판단되므로, 예문을 재생성할 때 함께 갱신합니다.

현재 앱의 단어 수정은 `words.json`만 갱신하며 예문 배치를 즉시 실행하지 않습니다. 최근 등록한 단어는 다음 배치에서 재생성을 시도하지만, **등록 후 7일이 지난 단어는 수정해도 재생성되지 않아 예문이 계속 숨겨질 수 있습니다.** 수정된 단어를 등록일과 무관하게 재생성하는 처리는 아직 구현되어 있지 않습니다.

## 데이터 저장과 백업

| 데이터 | 저장 위치와 역할 |
|---|---|
| [words.json](public/data/words.json) | 단어의 현재 값. ID, 표기, 읽기, 뜻, 품사, Step·레슨, 교재, 등록일 등을 저장 |
| [sentences.json](public/data/sentences.json) | `wordId`로 단어와 연결. 생성일, 생성 당시 단어 값(`source`), 예문·읽기·번역, 검사 결과(`check`: 판정일·통과 여부·숨긴 이유)를 저장 |
| IndexedDB (`words`, `sentences`) | 브라우저에서 열람·오프라인 학습에 사용하는 단어·예문 사본 |
| IndexedDB (`reviews`, `reviewLogs`) | 해당 브라우저의 FSRS 복습 상태와 평가 이력 |

단어·예문 파일은 GitHub의 `main` 브랜치에서 우선 가져오고, 실패하면 앱 배포본의 파일을 사용합니다. 복습 기록은 브라우저에 저장되며 기기 간 자동 동기화는 지원하지 않습니다.

설정의 **학습 기록 내보내기**는 단어·예문·복습 상태·평가 이력을 JSON으로 저장합니다. **학습 기록 가져오기**는 그중 복습 상태와 평가 이력만 복원하며, 기존 기록을 대체합니다. 단어와 예문은 저장소 데이터를 사용합니다.

## 키 설정

| 설정 | 용도 | 설정 위치 |
|---|---|---|
| [Gemini API 키](https://aistudio.google.com/apikey) | 교재 사진에서 단어 추출 | 앱의 설정 > Gemini API |
| [GitHub PAT (Fine-grained)](https://github.com/settings/personal-access-tokens/new) | 단어 저장·수정·삭제, 신규 등록 후 예문 배치 실행 요청 | 앱의 설정 > GitHub |
| `GEMINI_API_KEY` | GitHub Actions에서 예문 생성·검사 | 저장소의 Settings > Secrets and variables > Actions에 repository secret으로 등록 |

GitHub PAT는 대상 저장소의 **Contents: Read and write** 권한이 필요합니다. 신규 단어 저장 직후 예문 생성을 요청하려면 **Actions: Read and write** 권한도 부여합니다. 앱에 입력한 Gemini 키와 PAT는 해당 브라우저의 로컬 저장소에 저장되며, 예문 배치는 별도로 설정한 repository secret을 사용합니다.

## 로컬 개발

Node.js 24를 사용합니다([.nvmrc](.nvmrc)). nvm을 사용한다면 먼저 `nvm use`로 버전을 맞춥니다.

```bash
npm ci
npm run dev -- --host
```

[로컬 앱](http://localhost:5173/j-voca/)에서 확인합니다.
개발 서버에서는 현재 체크아웃의 단어·예문 JSON을 읽습니다. 배포 앱은 GitHub `main` 데이터를 우선 사용합니다.

빌드·미리보기·테스트:

```bash
npm run build
npm run preview
npm test
npm run test:watch
```

테스트는 FSRS 복습 계산, Step·레슨 및 단어 필터링, Gemini 응답 처리, 예문 유효성, 동사 활용 규칙·출제 큐, 실제 JSON 데이터의 정합성 등을 검증합니다.

예문 생성 배치를 로컬에서 실행하려면 `GEMINI_API_KEY` 환경 변수를 설정한 뒤 실행합니다. 생성 대상은 정기 배치와 같고, 결과는 로컬 `public/data/sentences.json`에 저장됩니다.

```bash
node scripts/generate-sentences.mjs
```

## 배포

[배포 워크플로](.github/workflows/deploy.yml)는 `main` 또는 `feature/*` 브랜치에 push하면 빌드한 `dist`를 GitHub Pages에 배포합니다. `words.json`·`sentences.json`만 바뀐 경우에는 배포를 실행하지 않으며, 앱이 저장소에서 최신 데이터를 직접 받습니다. 앱의 기본 경로는 `/j-voca/`입니다.
