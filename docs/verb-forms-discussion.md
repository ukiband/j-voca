# 동사 활용 기능 논의 메모

최종 정리: 2026-09-21. 2026-09-17의 초기 논의를 이어서, Step 2 목차와 화면 예시를 보며 확정한 설계다. 이 기준으로 동사 활용 기능과 기존 동사 분류 마이그레이션을 구현했다. 이 문서의 최신 방향은 이전의 ‘기존 단어 카드에 선택한 활용형을 함께 표시’하는 안을 대체한다.

## 목적과 기존 기능의 관계

단어장은 단어와 뜻을 외우는 역할을 유지한다. 사용자가 필요할 때 동사 변환을 집중해서 연습할 수 있도록 복습 화면에 **‘동사 활용’ 메뉴 하나를 추가**한다.

- 기존 단어 복습의 카드, 뜻, 예문, 모름·애매·앎 평가와 학습 기록은 유지한다.
- ‘함께 볼 활용형’ 선택기는 넣지 않는다. 일반 단어 복습 카드에 활용형 영역을 추가하지 않는다.
- 동사 활용은 단어 복습과 별개인 자유 연습이다. 오늘 복습할 차례인 단어로 제한하지 않는다.
- 동사 활용 결과는 단어의 FSRS 상태, 복습 일정, 학습 기록에 반영하지 않는다. 형태별 숙련도나 평가 기록도 만들지 않는다.
- 변환된 형태를 별도 단어로 등록하거나 단어 수를 늘리지 않는다.

## 메뉴 배치

현재 화면의 순서는 다음과 같다.

1. 전체 복습
2. **동사 활용**
3. Step 2 레슨 목록
4. Step 1 레슨 목록
5. 카테고리별 복습

중간에 Step 2와 Step 1 사이 배치도 검토했지만, 최종적으로 지금은 전체 복습 바로 아래에 두기로 했다.

나중에 Step 3를 배우기 시작하면 `전체 복습 → Step 3 → 동사 활용 → Step 2 → Step 1`처럼 조정할 수 있다는 방향을 이야기했다. 자동 이동 규칙을 구현하기로 정한 것은 아니다.

연습 대상은 Step에 관계없이 **사전형(원형)으로 등록된 동사**다. Step 1에서 배운 동사도 이 조건에 맞으면 포함하고, 첫 버전에 Step·레슨 범위 선택기를 두지 않는다.

## 지원 범위: 네 가지

| 형태 | 예시 | 첨부한 Step 2 목차 |
|---|---|---|
| 테형 | 書く → 書いて | Lesson 2, Lesson 3에서 응용 |
| 나이형 | 書く → 書かない | Lesson 4 |
| 타형 | 書く → 書いた | Lesson 6 |
| 가능형 | 書く → 書ける | Lesson 7 |

처음 지원할 대상은 위 네 가지로 제한한다. 현재 배우는 테형부터 선택해서 쓰고, 다른 형태는 배울 때 선택할 수 있도록 한다.

목차 전체를 별도 메뉴로 옮기지는 않는다. `ている`, `てください`, `てもいい` 같은 결합 표현, 수수표현, 복문표현, 보통체 종합 연습은 첫 버전의 별도 출제 항목으로 넣지 않는다. ます형도 별도 목표 형태로 추가하지 않는다. **문제 앞면은 사전형으로 통일**한다.

## 출제 범위와 문제 수

- Step·레슨 구분 없이 사전형으로 등록된 전체 동사를 대상으로 한다. 오늘 복습 일정이나 최근 등록 여부로 제한하지 않는다.
- `行く`, `書く`, `食べる`는 포함하고, `行きます`, `書いて`, `借り`처럼 사전형이 아닌 표기로 등록된 항목은 제외한다. 연습을 위해 사전형으로 복원하거나 별도 저장하지 않는다. 기존 단어 복습에서는 그대로 사용한다.
- 문제 수는 제한 없이 **전체**로 한다. 10개·20개 등 수량 선택기를 두지 않는다.
- 네 형태를 체크박스로 선택한다. 하나만 체크해 집중하거나 여러 형태를 자유롭게 조합할 수 있다.
- ‘동사 하나 + 선택한 형태 하나’를 한 문제로 보고, 선택한 형태의 모든 유효한 조합을 섞어 출제한다. 예를 들어 두 형태 모두 출제할 수 있는 동사 20개에 테형·타형을 선택하면 40문제다.
- 모두 풀어야 할 의무는 없다. 원하는 만큼 연습하고 나갈 수 있다.
- ‘동사 활용’에 새로 들어오면 순서를 다시 섞어 처음부터 시작한다. 이전 연습의 진행 상태나 ‘한 번 더’ 목록은 이어서 복원하지 않는다.
- 특정 시간 미접속 후 브라우저가 상태를 정리하는 동작에 의존하지 않는다. 새 연습 시작 시 초기화한다.

## 연습 화면과 동작

확정한 연습 흐름은 다음과 같다.

1. 복습 화면에서 ‘동사 활용’을 누른다.
2. 네 형태의 체크박스에서 원하는 형태를 선택하고 전체 문제로 시작한다.
3. 앞면의 동사 사전형과 요구하는 형태를 보고 정답을 떠올린다.
4. ‘뒤집기’를 눌러 변환 결과와 읽기, 짧은 변환 규칙을 확인한다.
5. ‘다음’으로 넘기거나, 헷갈렸다면 ‘한 번 더’를 눌러 이번 연습 뒤쪽에서 다시 본다.

앞면 예시:

> 書く（かく）
>
> て형으로 바꿔 보세요.

뒷면 예시:

> **書いて（かいて）**
>
> 1류 동사 · く → いて
>
> 한 번 더 / 다음

‘한 번 더’는 해당 세션의 반복 동작이며 장기 학습 기록이 아니다. 연습을 종료한 뒤 헷갈린 항목을 다음 세션까지 보관하는 기능은 현재 범위에 없다.

**첫 버전의 동사 활용 화면에서는 예문을 보여주지 않는다.** 기존 단어 복습의 예문은 계속 사용한다. 활용형의 한국어 뜻을 `書いて = 쓰고 나서`처럼 한 가지 문맥으로 고정하지 않는다.

## 활용형 준비 방식

테형·타형 등의 결과를 AI로 미리 생성해 저장하는 대신, **앱에서 공통 활용 규칙으로 동적으로 계산하는 방향**이다. 활용 정답을 만드는 데 API 호출이나 네트워크 연결이 필요하지 않다.

이를 위해 동사에 다음 정보를 정확히 준비해야 한다.

| 필요한 정보 | 예시 |
|---|---|
| 활용 기준이 되는 사전형 | 書く |
| 사전형 읽기 | かく |
| 동사 분류 | 1류 / 2류 / 3류 |

사전형으로 등록된 동사만 사용하므로 기존 표기·읽기를 그대로 활용하고 동사 분류만 추가한다. 연습용 사전형·읽기를 별도 필드로 저장하지 않는다. 사전형이 아닌 등록 항목을 연습용 사전형에 연결하는 처리도 만들지 않는다.

기존 단어의 표기·읽기·뜻은 보존한다. **기존 대상 동사는 분류 정보를 일괄 마이그레이션하고, 신규 단어 입력에서도 동사 분류를 함께 준비한다.** 신규 단어도 사전형으로 등록한 경우에만 연습 대상에 포함하며, 활용된 형태로 입력했다고 별도 사전형을 생성하지 않는다.

저장하는 필드는 `verbGroup`(1·2·3 또는 미확인 null), `isDictionaryForm`(사전형 여부), `potentialAllowed`(가능형 연습 적합성)다. 사진 추출 결과를 저장하기 전에 분류를 확인·수정할 수 있고, 기존 단어 수정 화면에서도 조정할 수 있다. 표기·읽기를 수정하면 분류를 초기화해 다시 확인하도록 한다.

- `行きます`만 등록되어 있다면 연습 대상에서 제외한다. `行く`가 별도 단어로 등록되어 있다면 그 항목은 포함한다.
- `ピアノを弾く`처럼 사전형 동사로 끝나는 구 단위 표현은 변환 대상 동사를 식별해 앞부분을 유지해야 한다.
- 표기와 읽기를 함께 변환한다. 읽기에서도 가타카나는 유지한다.
- `行く → 行って / 行った`, `来る → 来て（きて）/ 来た（きた）`, `ある → ない` 같은 예외는 공통 로직에서 처리한다.
- 가능형은 모든 동사를 무조건 변환해 출제하지 않고, 해당 동사에 적절한 연습인지 확인해야 한다.
- 동사 분류나 사전형 여부가 불명확한 항목은 확인 전까지 출제하지 않는다.

동사 입력 시 중요한 것은 **등록된 표기의 사전형 여부와 동사 분류를 확인하는 것**이다. 별도 사전형이나 형태별 정답을 미리 저장할 필요는 없다.

## 예문 관련 논의의 정리

동적 활용 계산과 미리 준비한 형태별 예문을 함께 사용하는 것은 가능하다. 그러나 이 경우 동사와 형태의 조합마다 자연스러운 예문·읽기·번역을 따로 준비하고 검토해야 한다. 단어의 어미를 바꾸는 것만으로 문장 전체와 번역을 정확하게 만들 수는 없다.

현재 목적은 동사 변환 암기이므로, 첫 버전은 예문 없이 진행하기로 했다. 따라서 이번 기능을 위해 형태별 예문 생성, 예문 저장 구조 확장, 앱 진도와 생성 작업의 동기화를 마련할 필요가 없다.

이전 메모의 ‘최근 7일 등록 단어에서 없는 형태별 예문만 생성’, ‘지원 형태 목록을 저장소에 두고 생성’ 등은 이번 기능의 확정 사항이 아니다. 일반 단어 예문의 생성 주기를 바꾸는 문제도 별도 논의이며, 동사 활용 기능에 포함하지 않는다. 앞으로 활용 예문이 필요해지면 다시 검토할 수 있다.

## 구현에서 정리한 세부 사항

| 항목 | 처리 방식 |
|---|---|
| 선택값 기억 | 연습 시작 시 체크한 형태만 기억. 최초 기본값은 て형. 학습 기록이나 진행 상태는 저장하지 않음 |
| 동사 정보의 저장 구조 | 위 세 메타데이터 필드로 분류. 별도 사전형·읽기 보완 필드는 만들지 않음 |
| 중복 단어 | 표기·읽기·분류가 같은 항목은 한 번 출제. 한자·가나 표기가 다른 항목이나 동음이의어는 각각 유지 |
| 출제 적합성 | 사전형과 분류가 확인된 항목만 포함. 가능형은 적합성이 확인된 조합만 포함하며, 같은 단어의 다른 형태는 계속 출제 |
| 추후 메뉴 위치 | Step 3 학습 시작 시 위치를 조정할 수 있지만 자동 이동 조건은 미정 |

기존 동사 173개를 검토해 사전형 143개와 제외 항목 30개로 분류했다. 출제 시 중복을 합치면 동사 121개이며, て형·ない형·た형은 각각 121문제, 가능형은 107문제다. 네 형태를 모두 고르면 470문제다. 마이그레이션은 기존 표기·읽기·뜻·ID를 바꾸지 않으며, 브라우저의 학습 기록에도 손대지 않는다.

초기 화면 예시는 논의용 시안이며, 실제 구현은 이 문서의 최종 범위를 따른다.
